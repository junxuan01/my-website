# 第 3 课：表关系设计

## 为什么需要多个表？

假设你在设计一个博客系统，最简单的做法是把所有信息放在一个表里：

```sql
-- ❌ 糟糕的设计
CREATE TABLE posts (
  id INT PRIMARY KEY,
  title VARCHAR(200),
  content TEXT,
  author_name VARCHAR(50),      -- 每篇文章都重复存作者名
  author_email VARCHAR(100),    -- 每篇文章都重复存邮箱
  author_bio TEXT               -- 每篇文章都重复存简介
);
```

**问题**：
- 数据冗余：同一个作者发了 100 篇文章，他的信息就存了 100 遍
- 更新困难：作者改名了，要更新 100 条记录
- 数据不一致：可能有些记录更新了，有些没更新

**正确做法**：拆分成多个表

## 一对多关系（1:N）

**最常见的关系**：一个用户可以写多篇文章

### 设计表结构

```sql
-- 用户表
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL,
  bio TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 文章表
CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL,
  content TEXT,
  user_id INT NOT NULL,                    -- 外键：指向作者
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  -- 可选：添加外键约束（实际项目中很少用）
  -- FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 插入数据

```sql
-- 1. 先插入用户
INSERT INTO users (username, email, bio) VALUES
('alice', 'alice@example.com', '全栈工程师'),
('bob', 'bob@example.com', '前端开发');

-- 2. 再插入文章
INSERT INTO posts (title, content, user_id) VALUES
('MySQL 入门', '这是内容...', 1),    -- alice 写的
('React 教程', '这是内容...', 1),    -- alice 写的
('Vue 实战', '这是内容...', 2);      -- bob 写的
```

### 查询：显示文章和作者

```sql
-- 使用 JOIN
SELECT 
  posts.id,
  posts.title,
  users.username as author,
  users.email
FROM posts
JOIN users ON posts.user_id = users.id;
```

**输出**：
```
+----+-------------+--------+-------------------+
| id | title       | author | email             |
+----+-------------+--------+-------------------+
|  1 | MySQL 入门  | alice  | alice@example.com |
|  2 | React 教程  | alice  | alice@example.com |
|  3 | Vue 实战    | bob    | bob@example.com   |
+----+-------------+--------+-------------------+
```

### 查询：某个用户的所有文章

```sql
SELECT * FROM posts WHERE user_id = 1;

-- 或者通过用户名查询
SELECT posts.* 
FROM posts
JOIN users ON posts.user_id = users.id
WHERE users.username = 'alice';
```

## 一对一关系（1:1）

**不常见，但有用**：一个用户对应一个用户详情

### 使用场景

- 用户基本信息（经常查询）：id、username、email
- 用户详细信息（很少查询）：address、phone、id_card

**为什么要分开**：
- 性能优化：查询用户列表时不需要加载详细信息
- 权限控制：详细信息更敏感，单独控制权限

### 设计表结构

```sql
-- 用户基本表
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(100) NOT NULL
);

-- 用户详情表（一对一）
CREATE TABLE user_profiles (
  user_id INT PRIMARY KEY,              -- 主键同时也是外键
  phone VARCHAR(20),
  address VARCHAR(200),
  birth_date DATE,
  
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 插入数据

```sql
-- 1. 插入用户
INSERT INTO users (username, email) VALUES ('alice', 'alice@example.com');

-- 2. 插入详情（user_id 必须对应存在的用户）
INSERT INTO user_profiles (user_id, phone, address) VALUES
(1, '13800138000', '北京市朝阳区');
```

### 查询

```sql
SELECT 
  users.username,
  users.email,
  user_profiles.phone,
  user_profiles.address
FROM users
LEFT JOIN user_profiles ON users.id = user_profiles.user_id
WHERE users.id = 1;
```

## 多对多关系（M:N）

**常见场景**：
- 学生 ↔ 课程（一个学生选多门课，一门课有多个学生）
- 文章 ↔ 标签（一篇文章有多个标签，一个标签属于多篇文章）

### 需要中间表

多对多关系**必须**用一个中间表来实现！

### 案例：文章和标签

```sql
-- 文章表
CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL,
  content TEXT
);

-- 标签表
CREATE TABLE tags (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL UNIQUE
);

-- 中间表：文章-标签关系
CREATE TABLE post_tags (
  post_id INT,
  tag_id INT,
  
  PRIMARY KEY (post_id, tag_id),         -- 联合主键
  FOREIGN KEY (post_id) REFERENCES posts(id),
  FOREIGN KEY (tag_id) REFERENCES tags(id)
);
```

### 插入数据

```sql
-- 1. 插入文章
INSERT INTO posts (title, content) VALUES
('MySQL 入门', '内容...'),
('Node.js 实战', '内容...'),
('React 教程', '内容...');

-- 2. 插入标签
INSERT INTO tags (name) VALUES
('数据库'),
('后端'),
('前端');

-- 3. 建立关系
INSERT INTO post_tags (post_id, tag_id) VALUES
(1, 1),  -- MySQL 入门 → 数据库
(1, 2),  -- MySQL 入门 → 后端
(2, 2),  -- Node.js 实战 → 后端
(3, 3);  -- React 教程 → 前端
```

### 查询：文章的所有标签

```sql
SELECT 
  posts.title,
  tags.name as tag
FROM posts
JOIN post_tags ON posts.id = post_tags.post_id
JOIN tags ON post_tags.tag_id = tags.id
WHERE posts.id = 1;
```

**输出**：
```
+-------------+--------+
| title       | tag    |
+-------------+--------+
| MySQL 入门  | 数据库 |
| MySQL 入门  | 后端   |
+-------------+--------+
```

### 查询：某个标签下的所有文章

```sql
SELECT 
  posts.id,
  posts.title
FROM posts
JOIN post_tags ON posts.id = post_tags.post_id
JOIN tags ON post_tags.tag_id = tags.id
WHERE tags.name = '后端';
```

**输出**：
```
+----+----------------+
| id | title          |
+----+----------------+
|  1 | MySQL 入门     |
|  2 | Node.js 实战   |
+----+----------------+
```

## 外键约束：用还是不用？

### 什么是外键约束？

```sql
CREATE TABLE posts (
  id INT PRIMARY KEY,
  user_id INT,
  
  FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE CASCADE      -- 删除用户时，自动删除他的文章
    ON UPDATE CASCADE      -- 更新用户ID时，自动更新文章的user_id
);
```

### 外键的好处

✅ 数据完整性：不能插入不存在的 user_id
✅ 级联操作：删除用户时自动删除相关数据

### 外键的问题

❌ 性能损耗：每次插入都要检查外键是否存在
❌ 锁开销：外键会增加锁的复杂度
❌ 分库分表困难：跨数据库无法使用外键

### 实际项目建议

**互联网项目**：
- ❌ 不用外键约束
- ✅ 在应用层（Node.js）保证数据一致性

```javascript
// 在代码里保证一致性
async function deleteUser(userId) {
  await db.beginTransaction();
  
  try {
    await db.query('DELETE FROM posts WHERE user_id = ?', [userId]);
    await db.query('DELETE FROM users WHERE id = ?', [userId]);
    await db.commit();
  } catch (error) {
    await db.rollback();
    throw error;
  }
}
```

**传统企业项目**：
- ✅ 可以用外键
- 数据一致性要求高，性能要求不高

## 实战练习

### 练习 1：设计电商订单系统

设计以下表：
- 用户表（users）
- 商品表（products）
- 订单表（orders）
- 订单详情表（order_items）

**关系**：
- 一个用户 → 多个订单
- 一个订单 → 多个商品（通过 order_items）
- 一个商品 → 多个订单（通过 order_items）

<details>
<summary>查看答案</summary>

```sql
-- 用户表
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(100) NOT NULL
);

-- 商品表
CREATE TABLE products (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100) NOT NULL,
  price DECIMAL(10, 2) NOT NULL,
  stock INT NOT NULL DEFAULT 0
);

-- 订单表
CREATE TABLE orders (
  id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  total_amount DECIMAL(10, 2) NOT NULL,
  status ENUM('pending', 'paid', 'shipped', 'completed') DEFAULT 'pending',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 订单详情表（中间表）
CREATE TABLE order_items (
  id INT PRIMARY KEY AUTO_INCREMENT,
  order_id INT NOT NULL,
  product_id INT NOT NULL,
  quantity INT NOT NULL,
  price DECIMAL(10, 2) NOT NULL       -- 下单时的价格（快照）
);
```

</details>

### 练习 2：查询订单详情

查询订单 ID 为 1 的所有商品信息：

<details>
<summary>查看答案</summary>

```sql
SELECT 
  orders.id as order_id,
  products.name as product_name,
  order_items.quantity,
  order_items.price,
  (order_items.quantity * order_items.price) as subtotal
FROM orders
JOIN order_items ON orders.id = order_items.order_id
JOIN products ON order_items.product_id = products.id
WHERE orders.id = 1;
```

## 总结

### 三种关系

| 关系类型 | 示例 | 实现方式 |
|---------|------|----------|
| **一对多** | 用户 → 文章 | 在"多"的一方加外键 |
| **一对一** | 用户 → 用户详情 | 任意一方加外键（通常用主键） |
| **多对多** | 文章 → 标签 | 创建中间表 |

### 设计原则

1. **避免数据冗余**：不要在多个表重复存储相同信息
2. **合理拆分表**：常用字段和不常用字段分开
3. **外键谨慎使用**：互联网项目一般不用外键约束
4. **中间表必须有**：多对多关系必须用中间表

### 前端类比

```javascript
// 一对多 = 数组
const user = {
  id: 1,
  name: 'Alice',
  posts: [
    { id: 1, title: 'Post 1' },
    { id: 2, title: 'Post 2' }
  ]
};

// 多对多 = 双向引用
const posts = [{ id: 1, tags: [1, 2] }];
const tags = [
  { id: 1, name: '数据库', posts: [1, 3] },
  { id: 2, name: '后端', posts: [1, 2] }
];
```
