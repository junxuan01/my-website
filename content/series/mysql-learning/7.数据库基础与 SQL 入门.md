# 数据库基础与 SQL 入门

SQL (Structured Query Language) 是一门声明式语言。你只需要告诉数据库"我想要什么"，而不需要告诉它"怎么做"（怎么做是执行引擎的事）。在这一章，我们将覆盖最常用的 CRUD 操作。

## 1. 核心概念：库与表

- **Database (数据库)**：一个项目通常对应一个 Database（比如 `my_blog`）。
- **Table (表)**：存放特定类型数据的集合（比如 `users`, `posts`）。
- **Column (列/字段)**：数据的属性（比如 `username`, `created_at`）。
- **Row (行/记录)**：一条具体的数据。

## 2. 数据定义语言 (DDL)

DDL (Data Definition Language) 用于定义库和表的结构。

### 创建数据库
```sql
-- 创建库，指定字符集为 utf8mb4（支持 emoji 🐶）
CREATE DATABASE IF NOT EXISTS my_blog 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

USE my_blog;
```

### 创建表 (Start simple)
我们设计一个简单的 `users` 表。

```sql
CREATE TABLE users (
    -- id: 主键，自增，无符号整数（不能是负数）
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    
    -- username: 字符串，最多 50 字，不能为空，必须唯一
    username VARCHAR(50) NOT NULL UNIQUE,
    
    -- email: 字符串，允许为空（假如允许非邮箱注册）
    email VARCHAR(100),
    
    -- age: 小整数，无符号
    age TINYINT UNSIGNED,
    
    -- status: 枚举类型，只能是这几个值之一，默认 'active'
    status ENUM('active', 'banned', 'inactive') DEFAULT 'active',
    
    -- created_at: 创建时间，默认为当前时间
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- updated_at: 更新时间，数据更新时自动刷新
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB COMMENT='用户信息表';
```

### 修改表结构
前端需求变了，要加个字段？
```sql
-- 添加列
ALTER TABLE users ADD COLUMN nickname VARCHAR(50) AFTER username;

-- 修改列类型
ALTER TABLE users MODIFY age INT; -- 把 TINYINT 改成 INT

-- 删除列
ALTER TABLE users DROP COLUMN nickname;
```

### 删除表
```sql
DROP TABLE IF EXISTS users;
```

## 3. 常用数据类型选择指南

前端只有 `Number`, `String`, `Boolean`, `Object`，但 MySQL 分得很细。

| 类别 | 类型 | 说明 | 前端类比 |
|------|------|------|----------|
| **整数** | `INT` | 常用 ID，范围 ±21 亿 | Number |
| | `BIGINT` | 超大 ID，如雪花算法 ID | BigInt |
| | `TINYINT` | 状态码，0-255。**`TINYINT(1)` 常用于 Boolean** | Boolean |
| **浮点** | `DECIMAL(M,D)` | **存钱必用！** 定点数，无精度丢失 | String (处理钱时) |
| | `FLOAT/DOUBLE` | 科学计算，会有精度问题 (0.1+0.2!=0.3) | Number |
| **字符串** | `VARCHAR(n)` | 变长字符串，最常用，n 是最大字符数 | String |
| | `CHAR(n)` | 定长，适合存 MD5、手机号、身份证 | String |
| | `TEXT` | 长文本，存文章内容 | String |
| **日期** | `DATETIME` | 8 字节，范围大，绝对时间 | Date Object |
| | `TIMESTAMP` | 4 字节，范围小 (到 2038 年)，带时区 | Date.now() / 1000 |
| **JSON** | `JSON` | 存配置、不规则属性 | JSON Object |

## 4. 数据操作语言 (DML) - CRUD

这是日常工作 90% 的内容。

### 增 (INSERT)
```sql
-- 标准插入
INSERT INTO users (username, email, age) 
VALUES ('xiaoming', 'xm@test.com', 18);

-- 批量插入
INSERT INTO users (username, email, age) 
VALUES 
('alice', 'a@test.com', 20),
('bob', 'b@test.com', 22);
```

### 查 (SELECT) - 重点！
```sql
-- 1. 基础查询
SELECT * FROM users; -- 生产环境慎用 *，最好写出列名

-- 2. 条件过滤 (WHERE)
SELECT id, username FROM users 
WHERE age >= 18 AND status = 'active';

-- 3. 模糊搜索 (LIKE)
-- 查找邮箱以 @test.com 结尾的用户
SELECT * FROM users WHERE email LIKE '%@test.com';

-- 4. 排序 (ORDER BY)
SELECT * FROM users ORDER BY created_at DESC;

-- 5. 分页 (LIMIT)
-- 取第 11 到 20 条（常考：LIMIT offset, count）
SELECT * FROM users LIMIT 10, 10;
```

### 改 (UPDATE)
⚠️ **警告**：写 `UPDATE` 时永远先写 `WHERE`，或者先跑一遍 `SELECT` 确认范围。忘写 `WHERE` 会更新全表！

```sql
UPDATE users 
SET age = 19, status = 'inactive'
WHERE id = 1;
```

### 删 (DELETE)
⚠️ **警告**：同样，忘写 `WHERE` 会清空全表！

```sql
DELETE FROM users WHERE id = 1;
```
**软删除 (Soft Delete)**：在实际项目中，我们很少真的 DELETE 数据，而是 update 一个 `deleted_at` 字段。
```sql
UPDATE users SET deleted_at = NOW() WHERE id = 1;
```
