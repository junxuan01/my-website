# 第 1 课：为什么需要数据库？

## 一个真实的故事

想象你正在开发一个待办事项应用。第一版很简单，你把数据存在 JavaScript 变量里：

```javascript
// 第一版：存在内存里
let todos = [
  { id: 1, title: '学习 React', done: false },
  { id: 2, title: '写博客', done: true }
];
```

**问题来了**：刷新页面，数据全没了。

于是你改用 `localStorage`：

```javascript
// 第二版：存在 localStorage
localStorage.setItem('todos', JSON.stringify(todos));
```

**新问题**：
- 数据只在浏览器里，换台电脑就没了
- 多个用户无法共享数据
- 无法在手机 App 和网页间同步

你意识到需要一个**后端服务器**来存储数据。但怎么存？

## 三种存储方案

### 方案 1：JSON 文件

```javascript
// server.js
const fs = require('fs');

// 读取
const todos = JSON.parse(fs.readFileSync('todos.json'));

// 添加新待办
todos.push({ id: 3, title: '买菜', done: false });

// 写入
fs.writeFileSync('todos.json', JSON.stringify(todos));
```

**问题**：
- ❌ 1000 个用户同时写入？文件会被覆盖或损坏
- ❌ 想找"所有未完成的待办"？需要读取整个文件再过滤
- ❌ 数据增长到 1GB 怎么办？内存爆了

### 方案 2：Excel/CSV 文件

类似问题，加上格式混乱的风险。

### 方案 3：数据库（MySQL）

```javascript
// 查询未完成的待办
SELECT * FROM todos WHERE done = false;

// 添加新待办
INSERT INTO todos (title, done) VALUES ('买菜', false);

// 标记完成
UPDATE todos SET done = true WHERE id = 3;
```

**数据库解决了什么？**
- ✅ **并发安全**：1000 人同时操作不会冲突
- ✅ **高效查询**：通过索引快速找到数据
- ✅ **数据完整性**：保证数据不丢失、不错乱
- ✅ **事务支持**：多个操作要么全成功，要么全失败
- ✅ **数据关系**：待办可以关联到用户、项目、标签

## 什么是 MySQL？

MySQL 是一个**关系型数据库管理系统**。用前端的概念类比：

| 前端概念 | MySQL 概念 | 说明 |
|---------|-----------|------|
| 对象数组 `[{...}, {...}]` | 表（Table） | 存储同类数据 |
| 对象 `{ id: 1, name: 'Alice' }` | 行（Row） | 一条记录 |
| 对象的属性 `name, email` | 列（Column） | 数据的字段 |
| `localStorage.getItem()` | `SELECT` | 查询数据 |
| `array.push()` | `INSERT` | 添加数据 |
| `array.filter()` | `WHERE` | 过滤数据 |

**实例对比**：

```javascript
// JavaScript
const users = [
  { id: 1, name: 'Alice', email: 'alice@ex.com' },
  { id: 2, name: 'Bob', email: 'bob@ex.com' }
];

const alice = users.find(u => u.name === 'Alice');
```

```sql
-- MySQL
SELECT * FROM users WHERE name = 'Alice';
```

**结果是一样的！**

```
+----+-------+--------------+
| id | name  | email        |
+----+-------+--------------+
|  1 | Alice | alice@ex.com |
+----+-------+--------------+
```

## MySQL 的简史（你可以跳过这部分）

**1995 年**：瑞典程序员 Monty Widenius 为自己的项目开发了 MySQL。名字来源于他女儿的名字"My"。

**2000-2008 年**：随着 LAMP（Linux + Apache + MySQL + PHP）技术栈的流行，MySQL 成为 Web 开发的标配：
- Google、Yahoo!、Facebook 早期都在用
- WordPress、Drupal 等 CMS 的默认数据库

**2008-2010 年**：Sun 收购 MySQL，Oracle 又收购 Sun。开源社区担心 MySQL 的未来，Monty 创建了分支 **MariaDB**。

**2018 年至今**：MySQL 8.0 是一个重大升级，性能提升 2 倍，加入了：
- JSON 原生支持
- 窗口函数
- CTE（公共表表达式）
- 更好的 Unicode 支持

**2024-2025**：MySQL 9.0 引入向量搜索（AI 集成），继续演进。

## MySQL vs 其他数据库（快速对比）

### MySQL vs PostgreSQL

```
MySQL:        快速、简单、适合 Web 应用
PostgreSQL:   功能强大、严谨、适合复杂查询

前端类比：
MySQL =       Express.js（简单直接）
PostgreSQL =  Koa.js（功能丰富）
```

### MySQL vs MongoDB

```
MySQL:        关系型（SQL）、表格结构
MongoDB:      文档型（NoSQL）、JSON 结构

前端类比：
MySQL =       TypeScript（有严格类型）
MongoDB =     JavaScript（灵活但需自律）
```

**什么时候用 MySQL？**
- ✅ 数据结构清晰（用户、订单、产品）
- ✅ 需要复杂的关联查询
- ✅ 数据完整性很重要（金融、电商）
- ✅ 团队熟悉 SQL

**什么时候用 MongoDB？**
- ✅ 数据结构经常变化
- ✅ 嵌套数据多（评论的回复的点赞...）
- ✅ 快速原型开发

## 为什么前端要学 MySQL？

### 1. 理解后端 API

当后端说"这个接口慢，要做分页"，你会理解他在说什么：

```javascript
// 前端请求
fetch('/api/users?page=1&limit=20')

// 后端 SQL（MySQL 分页）
SELECT * FROM users 
LIMIT 20 OFFSET 0;  -- 第 1 页
```

### 2. 设计更好的数据结构

知道数据库原理后，你的 API 设计会更合理：

```javascript
// ❌ 糟糕的设计（N+1 查询问题）
GET /users        // 获取用户列表
GET /posts/:userId // 为每个用户获取文章（循环请求）

// ✅ 好的设计（JOIN 一次性获取）
GET /users?include=posts
```

### 3. 全栈开发能力

前端：React/Vue → 后端：Node.js + Express → 数据库：MySQL

你可以独立完成整个产品！

### 4. 面试加分项

很多公司面试会问：
- "解释一下索引是什么？"
- "什么是 SQL 注入？"
- "N+1 查询问题怎么解决？"

懂 MySQL，你就能自信回答。

## 真实案例：一个博客系统

假设你要开发一个博客，需要存储：
- 用户（authors）
- 文章（posts）
- 评论（comments）
- 标签（tags）

**在 MySQL 中的结构**：

```sql
-- 用户表
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 文章表
CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL,
  content TEXT,
  author_id INT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (author_id) REFERENCES users(id)
);

-- 评论表
CREATE TABLE comments (
  id INT PRIMARY KEY AUTO_INCREMENT,
  post_id INT,
  user_id INT,
  content TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (post_id) REFERENCES posts(id),
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**查询"Alice 写的所有文章"**：

```sql
SELECT posts.* 
FROM posts 
JOIN users ON posts.author_id = users.id 
WHERE users.username = 'Alice';
```

**在 JavaScript 中**：

```javascript
const alicePosts = posts.filter(post => {
  const author = users.find(u => u.id === post.author_id);
  return author.username === 'Alice';
});
```

**看到了吗？逻辑是一样的，只是语法不同。**

## MySQL 生态系统

### Node.js 中使用 MySQL

```javascript
// 安装
npm install mysql2

// 连接
const mysql = require('mysql2/promise');

const connection = await mysql.createConnection({
  host: 'localhost',
  user: 'root',
  password: 'password',
  database: 'myblog'
});

// 查询
const [rows] = await connection.execute(
  'SELECT * FROM users WHERE email = ?',
  ['alice@example.com']
);

console.log(rows[0]); 
// { id: 1, username: 'Alice', email: 'alice@example.com' }
```
