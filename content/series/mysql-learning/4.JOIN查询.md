# 第 4 课：JOIN 查询

## 为什么需要 JOIN？

数据分散在多个表中，但我们需要把它们组合起来查询：

```sql
-- 想要这样的结果：
+----+-------------+--------+-------------------+
| id | title       | author | email             |
+----+-------------+--------+-------------------+
|  1 | MySQL 入门  | alice  | alice@example.com |
|  2 | React 教程  | alice  | alice@example.com |
+----+-------------+--------+-------------------+

-- 数据分散在两个表：
users: id | username | email
posts: id | title    | user_id
```

**JOIN** 就是把多个表"连接"起来查询的方法。

## 准备测试数据

```sql
-- 创建表
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(100)
);

CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL,
  user_id INT
);

-- 插入数据
INSERT INTO users (username, email) VALUES
('alice', 'alice@example.com'),
('bob', 'bob@example.com'),
('charlie', 'charlie@example.com');  -- charlie 没发过文章

INSERT INTO posts (title, user_id) VALUES
('MySQL 入门', 1),    -- alice 的
('React 教程', 1),    -- alice 的
('Node.js 实战', 2),  -- bob 的
('孤儿文章', 999);    -- user_id 不存在的文章
```

## INNER JOIN（内连接）

**只返回两个表都匹配的数据**

### 语法

```sql
SELECT 
  posts.id,
  posts.title,
  users.username
FROM posts
INNER JOIN users ON posts.user_id = users.id;
```

**输出**：
```
+----+----------------+----------+
| id | title          | username |
+----+----------------+----------+
|  1 | MySQL 入门     | alice    |
|  2 | React 教程     | alice    |
|  3 | Node.js 实战   | bob      |
+----+----------------+----------+
```

**注意**：
- ❌ "孤儿文章"没出现（user_id=999 不存在）
- ❌ charlie 没出现（他没发过文章）

### 简写

```sql
-- INNER 可以省略
SELECT * FROM posts JOIN users ON posts.user_id = users.id;

-- 使用别名（推荐）
SELECT 
  p.id,
  p.title,
  u.username,
  u.email
FROM posts p
JOIN users u ON p.user_id = u.id;
```

### 前端类比

```javascript
// INNER JOIN = 两个数组的交集
const posts = [
  { id: 1, title: 'MySQL 入门', user_id: 1 },
  { id: 2, title: 'React 教程', user_id: 1 },
  { id: 3, title: 'Node.js 实战', user_id: 2 },
  { id: 4, title: '孤儿文章', user_id: 999 }
];

const users = [
  { id: 1, username: 'alice' },
  { id: 2, username: 'bob' },
  { id: 3, username: 'charlie' }
];

// INNER JOIN 结果
const result = posts
  .map(post => {
    const user = users.find(u => u.id === post.user_id);
    return user ? { ...post, username: user.username } : null;
  })
  .filter(item => item !== null);
```

## LEFT JOIN（左连接）

**返回左表的所有数据，右表匹配不上的显示 NULL**

### 语法

```sql
SELECT 
  posts.id,
  posts.title,
  users.username
FROM posts
LEFT JOIN users ON posts.user_id = users.id;
```

**输出**：
```
+----+----------------+----------+
| id | title          | username |
+----+----------------+----------+
|  1 | MySQL 入门     | alice    |
|  2 | React 教程     | alice    |
|  3 | Node.js 实战   | bob      |
|  4 | 孤儿文章       | NULL     |  ← 出现了！
+----+----------------+----------+
```

**用途**：找出有问题的数据

```sql
-- 找出 user_id 不存在的文章（数据错误）
SELECT * FROM posts
LEFT JOIN users ON posts.user_id = users.id
WHERE users.id IS NULL;
```

### 反向 LEFT JOIN

```sql
-- 左表是 users，显示所有用户
SELECT 
  users.username,
  posts.title
FROM users
LEFT JOIN posts ON users.id = posts.user_id;
```

**输出**：
```
+----------+----------------+
| username | title          |
+----------+----------------+
| alice    | MySQL 入门     |
| alice    | React 教程     |
| bob      | Node.js 实战   |
| charlie  | NULL           |  ← charlie 没发过文章
+----------+----------------+
```

**用途**：找出没发过文章的用户

```sql
SELECT users.username
FROM users
LEFT JOIN posts ON users.id = posts.user_id
WHERE posts.id IS NULL;
```

**输出**：`charlie`

## RIGHT JOIN（右连接）

**和 LEFT JOIN 相反**，返回右表的所有数据。

```sql
-- 这两个查询结果相同
SELECT * FROM posts LEFT JOIN users ON posts.user_id = users.id;
SELECT * FROM users RIGHT JOIN posts ON users.id = posts.user_id;
```

**实际开发**：很少用 RIGHT JOIN，都用 LEFT JOIN（把表换个位置就行了）。

## 多表 JOIN

### 三表 JOIN

```sql
-- 用户 → 文章 → 评论
SELECT 
  users.username as author,
  posts.title,
  comments.content as comment
FROM users
JOIN posts ON users.id = posts.user_id
JOIN comments ON posts.id = comments.post_id;
```

### 多对多关系的 JOIN

```sql
-- 查询文章和它的所有标签
SELECT 
  posts.title,
  tags.name as tag
FROM posts
JOIN post_tags ON posts.id = post_tags.post_id
JOIN tags ON post_tags.tag_id = tags.id
WHERE posts.id = 1;
```

## 聚合函数

### COUNT - 统计数量

```sql
-- 统计每个用户发了多少篇文章
SELECT 
  users.username,
  COUNT(posts.id) as post_count
FROM users
LEFT JOIN posts ON users.id = posts.user_id
GROUP BY users.id, users.username;
```

**输出**：
```
+----------+------------+
| username | post_count |
+----------+------------+
| alice    |          2 |
| bob      |          1 |
| charlie  |          0 |
+----------+------------+
```

**关键点**：
- `COUNT(posts.id)` 统计文章数（NULL 不计数）
- `GROUP BY users.id` 按用户分组

### SUM - 求和

```sql
-- 统计每个用户的订单总金额
SELECT 
  users.username,
  SUM(orders.amount) as total_spent
FROM users
LEFT JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.username;
```

### AVG - 平均值

```sql
-- 统计每个商品的平均评分
SELECT 
  products.name,
  AVG(reviews.rating) as avg_rating
FROM products
LEFT JOIN reviews ON products.id = reviews.product_id
GROUP BY products.id, products.name;
```

### MAX / MIN

```sql
-- 每个用户最新的一篇文章
SELECT 
  users.username,
  MAX(posts.created_at) as latest_post
FROM users
LEFT JOIN posts ON users.id = posts.user_id
GROUP BY users.id, users.username;
```

## GROUP BY 和 HAVING

### GROUP BY - 分组

```sql
-- 按用户分组，统计文章数
SELECT 
  user_id,
  COUNT(*) as post_count
FROM posts
GROUP BY user_id;
```

### HAVING - 过滤分组结果

```sql
-- 找出发了超过 1 篇文章的用户
SELECT 
  users.username,
  COUNT(posts.id) as post_count
FROM users
JOIN posts ON users.id = posts.user_id
GROUP BY users.id, users.username
HAVING COUNT(posts.id) > 1;
```

**WHERE vs HAVING**：

```sql
-- WHERE: 过滤原始数据（分组前）
-- HAVING: 过滤分组结果（分组后）

SELECT 
  user_id,
  COUNT(*) as post_count
FROM posts
WHERE created_at > '2024-01-01'    -- WHERE 在分组前过滤
GROUP BY user_id
HAVING COUNT(*) > 5;                -- HAVING 在分组后过滤
```

## 实战案例

### 案例 1：用户活跃度排行

```sql
-- 查询发文最多的前 10 名用户
SELECT 
  users.username,
  COUNT(posts.id) as post_count
FROM users
LEFT JOIN posts ON users.id = posts.user_id
GROUP BY users.id, users.username
ORDER BY post_count DESC
LIMIT 10;
```

### 案例 2：文章和评论数

```sql
-- 显示每篇文章的评论数
SELECT 
  posts.id,
  posts.title,
  COUNT(comments.id) as comment_count
FROM posts
LEFT JOIN comments ON posts.id = comments.post_id
GROUP BY posts.id, posts.title
ORDER BY comment_count DESC;
```

### 案例 3：找出没人选的课程

```sql
-- 哪些课程还没有学生选修？
SELECT courses.name
FROM courses
LEFT JOIN enrollments ON courses.id = enrollments.course_id
WHERE enrollments.id IS NULL;
```

### 案例 4：订单统计

```sql
-- 每个用户的订单总数和总金额
SELECT 
  users.username,
  COUNT(orders.id) as order_count,
  COALESCE(SUM(orders.amount), 0) as total_amount
FROM users
LEFT JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.username
ORDER BY total_amount DESC;
```

**COALESCE**：如果 SUM 结果是 NULL，返回 0。

## 常见错误

### 错误 1：忘记 GROUP BY

```sql
-- ❌ 错误
SELECT 
  users.username,
  COUNT(posts.id)
FROM users
JOIN posts ON users.id = posts.user_id;
-- ERROR: users.username not in GROUP BY

-- ✅ 正确
SELECT 
  users.username,
  COUNT(posts.id)
FROM users
JOIN posts ON users.id = posts.user_id
GROUP BY users.id, users.username;
```

### 错误 2：WHERE 和 HAVING 混淆

```sql
-- ❌ 错误：HAVING 中不能用别名
SELECT user_id, COUNT(*) as cnt
FROM posts
GROUP BY user_id
HAVING cnt > 1;  -- ERROR

-- ✅ 正确
HAVING COUNT(*) > 1;
```

### 错误 3：笛卡尔积

```sql
-- ❌ 危险：忘记 ON 条件
SELECT * FROM posts, users;
-- 结果：posts 的每一行 × users 的每一行 = 笛卡尔积

-- ✅ 正确
SELECT * FROM posts JOIN users ON posts.user_id = users.id;
```

## 总结

### JOIN 类型

| JOIN 类型 | 说明 | 使用场景 |
|----------|------|----------|
| **INNER JOIN** | 只返回匹配的行 | 查询有关联的数据 |
| **LEFT JOIN** | 返回左表全部 + 右表匹配 | 找缺失数据、保留左表 |
| **RIGHT JOIN** | 返回右表全部 + 左表匹配 | 很少用（用 LEFT JOIN 代替） |

### 聚合函数

- `COUNT(*)` - 统计行数
- `SUM(column)` - 求和
- `AVG(column)` - 平均值
- `MAX(column)` - 最大值
- `MIN(column)` - 最小值

### 关键语句顺序

```sql
SELECT ...       -- 5. 选择列
FROM table1      -- 1. 从哪个表
JOIN table2      -- 2. 连接其他表
WHERE ...        -- 3. 过滤数据
GROUP BY ...     -- 4. 分组
HAVING ...       -- 6. 过滤分组
ORDER BY ...     -- 7. 排序
LIMIT ...        -- 8. 限制数量
```

## 补充：子查询

子查询就是把一个查询嵌套在另一个查询里。

### WHERE 中的子查询

```sql
-- 查询发过文章的用户
SELECT * FROM users 
WHERE id IN (SELECT DISTINCT user_id FROM posts);

-- 查询没发过文章的用户
SELECT * FROM users 
WHERE id NOT IN (SELECT DISTINCT user_id FROM posts);
```

### 作为临时表

```sql
-- 查询发文数超过平均值的用户
SELECT user_id, post_count
FROM (
  SELECT user_id, COUNT(*) as post_count
  FROM posts
  GROUP BY user_id
) as user_stats
WHERE post_count > (SELECT AVG(post_count) FROM (
  SELECT COUNT(*) as post_count FROM posts GROUP BY user_id
) as avg_stats);
```

### 子查询 vs JOIN

```sql
-- 子查询写法
SELECT * FROM users 
WHERE id IN (SELECT user_id FROM posts WHERE status = 'published');

-- JOIN 写法（通常性能更好）
SELECT DISTINCT users.* 
FROM users 
JOIN posts ON users.id = posts.user_id 
WHERE posts.status = 'published';
```

**建议**：能用 JOIN 就用 JOIN，子查询在复杂场景下更灵活。
