# JSON 与现代特性

"为什么要用 MongoDB？因为可以存 JSON，Schema 灵活。"
MySQL 听了微微一笑："我也行啊，而且我还能 JOIN。"

从 MySQL 5.7 开始引入 JSON 类型，到 8.0 变得非常成熟。这让 MySQL 变成了 **多模数据库 (Multi-Model Database)**。

## 1. 为什么要存 JSON？

- **用户画像/配置**：每个人设置项不一样，不用建几百个列。
- **外部 API 结果**：调用微信支付 API，返回的一大坨结果想原样存下来备查。
- **动态表单**：CMS 系统里，文章可能有不固定的属性。

## 2. 基础操作

### 建表
```sql
CREATE TABLE products (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    attributes JSON -- 定义 JSON 类型
);
```

### 插入
直接插 JSON 字符串或对象 (Node.js)。
```sql
INSERT INTO products VALUES (1, 'T-Shirt', '{"color": "red", "size": "L", "tags": ["cotton", "summer"]}');
```

### 查询 (Magic happens here)
用 `->` (提取包含引号) 或 `->>` (提取纯文本，Unquote)。

```sql
-- 查所有红色衣服
-- $.color 意思是根节点下的 color 属性
SELECT * FROM products 
WHERE attributes->>'$.color' = 'red';

-- 查包含 'cotton' 标签的（JSON 数组查询）
SELECT * FROM products 
WHERE JSON_CONTAINS(attributes->'$.tags', '"cotton"');
```

### 更新
不需要把整个 JSON 拿出来改完再塞回去，可以直接改里面一个字段！

```sql
-- 把 size 改成 XL
UPDATE products 
SET attributes = JSON_SET(attributes, '$.size', 'XL')
WHERE id = 1;
```

## 3. 虚拟列 (Generated Columns) 与索引

"存 JSON 爽是爽，查询会不会慢？"
如果你直接查 `WHERE attributes->>'$.color' = 'red'`，是全表扫描，慢。

**解决办法：虚拟列 + 索引**
MySQL 可以不仅仅给物理列加索引，还能给"计算出来的虚拟列"加索引。

```sql
-- 1. 创建一个虚拟列 color，它的值自动从 JSON 里提取
ALTER TABLE products 
ADD COLUMN color VARCHAR(20) 
GENERATED ALWAYS AS (attributes->>'$.color') VIRTUAL;

-- 2. 给这个虚拟列加索引
CREATE INDEX idx_color ON products(color);
```

**效果**：
现在你跑 `SELECT * FROM products WHERE color = 'red'`，它走的是 B+ 树索引，和普通列一样快！而且这个列不占存储空间（VIRTUAL），索引占空间。

这是 MySQL 反击 MongoDB 的杀手锏。

## 4. 窗口函数 (Window Functions)

在 MySQL 8.0 之前，要查"每个班级的前三名"，属于 SQL 里的噩梦级难题。
现在有了窗口函数，非常优雅。

```sql
SELECT 
    student_name, 
    class_id, 
    score,
    -- RANK() over ... 这就是窗口函数
    RANK() OVER (PARTITION BY class_id ORDER BY score DESC) as ranking
FROM scores;
```
这就直接算出了排名。

## 5. CTE (Common Table Expressions)

公用表表达式。用 `WITH` 语法，让复杂的嵌套查询变得像代码里的变量一样可读。

```sql
-- 以前的写法：嵌套地狱
SELECT * FROM (SELECT ... FROM (SELECT ...))

-- CTE 写法：优雅
WITH top_users AS (
    SELECT user_id FROM orders GROUP BY user_id HAVING SUM(amount) > 1000
),
user_details AS (
    SELECT * FROM users WHERE id IN (SELECT user_id FROM top_users)
)
SELECT * FROM user_details;
```
