# 视图、存储过程与触发器

这三个特性属于"数据库编程"的范畴。在现代互联网架构（特别是微服务和前后端分离）中，业务逻辑通常都在应用层（Node.js/Java/Go），**这三个特性用得越来越少**。但作为知识体系，你是必须知道的。

## 1. 视图 (View)

视图是一个**虚拟表**。它不存数据，只存 SQL 逻辑。

**场景**：
你有一个超复杂的报表查询，关联了 5 张表，写出来 SQL 有 50 行。你不想每次都写这么一大坨。

```sql
-- 创建视图
CREATE VIEW v_active_users_report AS
SELECT u.username, o.total_amount, p.product_name
FROM users u
JOIN orders o ON u.id = o.user_id
JOIN order_items oi ON o.query_id = oi.order_id
JOIN products p ON oi.product_id = p.id
WHERE u.status = 'active';

-- 使用视图（就像查普通表一样）
SELECT * FROM v_active_users_report WHERE total_amount > 1000;
```

**优点**：
- **简化代码**：复用复杂 SQL。
- **安全**：可以只给前端开发者开放 View 的权限，不给底层 Table 的权限，隐藏敏感字段（如 phone, password）。

## 2. 存储过程 (Stored Procedure)

存储过程就是**存在数据库里的函数**。可以包含 `if/else`, `while`, 变量声明等逻辑。

```sql
DELIMITER // -- 修改分隔符，因为过程里有分号

CREATE PROCEDURE CreateOrder(IN userId INT, IN productId INT)
BEGIN
    DECLARE stock INT;
    
    -- 1. 查库存
    SELECT quantity INTO stock FROM products WHERE id = productId;
    
    -- 2. 判断逻辑
    IF stock > 0 THEN
        INSERT INTO orders(user_id, product_id) VALUES(userId, productId);
        UPDATE products SET quantity = quantity - 1 WHERE id = productId;
    ELSE
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Out of Stock';
    END IF;
END //

DELIMITER ; -- 改回来
```

**调用**：
```sql
CALL CreateOrder(1, 10086);
```

**争议**：
- **优点**：运行在数据库端，减少网络传输，性能高（理论上）。
- **缺点（现代观点）**：
  - **难以调试**：没有像 Chrome DevTools 那样的调试器。
  - **难以版本控制**：Git 存 SQL 文件不如存 JS 代码方便。
  - **迁移困难**：MySQL 的存储过程和 Oracle/PG 的语法完全不同。
- **建议**：除非是极度追求性能的内部系统，否则**尽量把逻辑写在 Node.js service 层**。

## 3. 触发器 (Trigger)

触发器是**数据库的 Event Listener**。
当发生 `INSERT/UPDATE/DELETE` 事件**之前 (BEFORE)** 或 **之后 (AFTER)**，自动执行一段代码。

**场景**：
不管业务层怎么改数据，我都要在 `audit_log` 表里记一笔"谁在什么时候改了什么"。

```sql
CREATE TRIGGER before_user_update
BEFORE UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (user_id, old_email, new_email, changed_at)
    VALUES (OLD.id, OLD.email, NEW.email, NOW());
END;
```

**使用建议**：
- 适合做**审计日志**、**数据完整性约束**。
- **慎用**：触发器是隐式的。新来的同事可能改了行代码，完全不知道背后悄悄触发了 10 个操作，导致 Debug 极其困难。

## 4. 总结

在传统的软件开发（如银行、ERP）中，这三者是重头戏。但在互联网敏捷开发中：

- **视图**：偶尔用，方便报表。
- **存储过程**：极少用，逻辑上移到应用层。
- **触发器**：少用，逻辑上移，或使用 Message Queue。
