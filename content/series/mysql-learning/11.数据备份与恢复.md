# 数据备份与恢复

作为开发者，最可怕的噩梦不是写出 Bug，而是**删库**（Drop Database）。数据是公司最重要的资产，备份是最后的救命稻草。不仅 DBA 要懂，全栈工程师也必须掌握基本的备份恢复技能。

## 1. 备份的类型

### 1.1 逻辑备份 (Logical Backup)
- **原理**：把数据库导出成一个巨大的 SQL 文本文件（包含 `CREATE TABLE`, `INSERT` 语句）。
- **工具**：`mysqldump`。
- **优点**：通用性强，是个文本文件，可以用编辑器看，跨版本迁移方便。
- **缺点**：恢复慢（因为要重跑一遍 SQL），对于几十 G 的数据会很慢。

### 1.2 物理备份 (Physical Backup)
- **原理**：直接复制数据库底层的文件（Data Directory）。
- **工具**：`Percona XtraBackup`, `mysqlbackup` (企业版)。
- **优点**：飞快（尤其是恢复），适合 TB 级大数据。
- **缺点**：不跨平台（Linux 的备份不能直接拷到 Windows 用）。

## 2. 使用 mysqldump（最常用）

对于中小型项目（< 10GB），`mysqldump` 是标准选择。

### 备份 (导出)
```bash
# 备份单个库
# > 符号是重定向，把输出写入文件
mysqldump -u root -p my_blog > my_blog_backup.sql

# 备份所有库（全量备份）
mysqldump -u root -p --all-databases > all_backup.sql

# 仅备份结构（不要数据，主要用于导出一份 Schema 给别人）
mysqldump -u root -p --no-data my_blog > schema.sql
```

**常见参数**：
- `--single-transaction`：**非常重要！** 在 InnoDB 下，这会在备份开始时开启一个事务，保证备份的数据是一致的 snapshot，而且**不锁表**。如果不加这个参数，备份期间表会被锁住，网站就挂了。
- `--routines` (`-R`)：连同存储过程和函数一起备。
- `--triggers`：连同触发器一起备。

**最佳实践命令**：
```bash
mysqldump -u root -p --single-transaction --routines --triggers --events my_blog > backup_$(date +%F).sql
```

### 恢复 (导入)
恢复逻辑备份非常简单，就是执行那个 SQL 文件。

```bash
# 1. 在 shell 中
mysql -u root -p my_blog < my_blog_backup.sql

# 2. 或者在 mysql 命令行中
# mysql> USE my_blog;
# mysql> SOURCE /path/to/my_blog_backup.sql;
```

## 3. 面试题：binlog (二进制日志)

除了全量备份，我们还需要**增量备份**。比如你每天凌晨 3 点备份一次，如果下午 5 点数据库挂了，你只能恢复到凌晨 3 点的数据吗？3 点到 5 点的数据丢了吗？

**不会，如果你开启了 binlog。**

- **binlog**：记录了所有**修改**了数据库的 SQL 语句（SELECT 不记）。
- **作用**：
  1. **主从复制**：Slave 读取 Master 的 binlog 来同步数据。
  2. **Point-in-Time Recovery (PITR)**：基于时间点的恢复。

**恢复流程**：
1. 先恢复凌晨 3 点的全量备份。
2. 找到凌晨 3 点到下午 5 点之间的 binlog 文件。
3. 使用 `mysqlbinlog` 工具重放这期间的操作。

```bash
# 重放 binlog
mysqlbinlog --start-datetime="2026-01-14 03:00:00" \
            --stop-datetime="2026-01-14 17:00:00" \
            binlog.000001 | mysql -u root -p
```

## 4. 自动备份策略

不要只人工备份，要写脚本自动跑。

1. **编写 Shell 脚本**：包含 mysqldump 命令，文件名加上时间戳。
2. **Cron 定时任务**：Linux `crontab -e` 设置每天凌晨执行脚本。
3. **异地灾备**：脚本要把备份文件上传到 AWS S3 / 阿里云 OSS。**备份文件和数据库放在同一台服务器上等于没备份**（服务器硬盘坏了就全完了）。
