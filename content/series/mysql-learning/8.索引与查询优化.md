# 索引与查询优化

如果你问我面试中最常被问到的 MySQL 问题是什么，答案一定是 **"索引"**。索引是数据库性能优化的基石，它能让查询速度从几秒提升到几毫秒。

## 1. 什么是索引？

> **比喻**：索引就像书籍的**目录**。
> - 如果没有目录（全表扫描），你要找"闭包"这个词，得从第一页翻到最后一页。
> - 有了目录（走索引），你可以直接翻到第 156 页。

在 MySQL (InnoDB) 中，索引不仅仅是目录，数据本身就是按索引组织的（聚簇索引）。

## 2. 索引底层结构：B+ 树

MySQL 主要使用 **B+ Tree** 作为索引结构。虽然前端不需要手写 B+ 树，但需要理解它的特性：

1. **有序性**：B+ 树的所有叶子节点是按顺序排列的双向链表。
   - 这意味着：范围查询（`WHERE age > 18`）和排序（`ORDER BY age`）非常快。
2. **层级低**：通常 3-4 层就能存几千万数据。
   - 这意味着：查一条数据只需要 3-4 次磁盘 I/O。

## 3. 索引的类型

### 3.1 聚簇索引 (Clustered Index)
- **就是主键索引**。
- 叶子节点直接存储**整行数据**。
- 一张表只能有一个聚簇索引。

### 3.2 二级索引 (Secondary Index) / 辅助索引
- 给普通字段（如 `username`）加的索引。
- 叶子节点存储的是 **主键 ID**。
- **回表 (Lookback)**：如果你通过 `username` 索引查 `email`，数据库会先在 `username` 索引树找到 ID，再拿着 ID 去聚簇索引树找整行数据。这个过程叫回表。

### 3.3 覆盖索引 (Covering Index)
- 如果你的查询只需要 ID 和索引列本身，不需要回表。
- 例子：`SELECT id FROM users WHERE username = 'alice';` 就触发了覆盖索引，速度极快。

## 4. 如何创建索引？

```sql
-- 建表时创建
CREATE TABLE orders (
    id INT PRIMARY KEY,
    order_no VARCHAR(20),
    user_id INT,
    KEY idx_user_id (user_id) -- 普通索引
);

-- 后期添加
-- 1. 普通索引
CREATE INDEX idx_email ON users(email);

-- 2. 唯一索引（既加速查询，又约束唯一性）
CREATE UNIQUE INDEX idx_username ON users(username);

-- 3. 联合索引（最重要！）
CREATE INDEX idx_name_age ON users(name, age);
```

## 5. 最左前缀原则 (The Leftmost Prefix Rule)

这是面试必考题，也是很多新手容易踩的坑。
对于联合索引 `(a, b, c)`：

- ✅ `WHERE a = 1` （用到索引）
- ✅ `WHERE a = 1 AND b = 2` （用到索引）
- ✅ `WHERE a = 1 AND b = 2 AND c = 3` （用到索引）
- ❌ `WHERE b = 2` （**用不到索引**！跳过了大哥 a）
- ❌ `WHERE c = 3` （用不到）
- ⚠️ `WHERE a = 1 AND c = 3` （只用到 a 的索引，c 用不到）

**比喻**：索引是按 "姓+名" 排序的电话簿。
- 找 "张三" (a+b)：快。
- 找 "姓张的人" (a)：快。
- 找 "名是三的人" (b)：没法找，必须从头翻。

## 6. 使用 EXPLAIN 分析查询

`EXPLAIN` 命令是 SQL 优化的手术刀。在 SELECT 前加上它，就能看到查询计划。

```sql
EXPLAIN SELECT * FROM users WHERE email = 'test@test.com';
```

**重点关注的字段**：

| 字段 | 含义 | 期望值 | 糟糕值 |
|------|------|--------|--------|
| **type** | 访问类型 | `const` (最快), `ref`, `range` | `ALL` (全表扫描 ❌) |
| **key** | 实际使用的索引 | 你的索引名 | `NULL` (没用到索引 ❌) |
| **rows** | 扫描行数 | 越少越好 | 几万+ |
| **Extra** | 额外信息 | `Using index` (覆盖索引 ✅) | `Using filesort` (文件排序 ❌), `Using temporary` (临时表 ❌) |

## 7. 常见慢查询优化策略

1. **避免 `SELECT *`**：只查需要的字段，增加覆盖索引的几率。
2. **避免在索引列上做计算**：
   - ❌ `WHERE YEAR(created_at) = 2023` (函数破坏索引)
   - ✅ `WHERE created_at BETWEEN '2023-01-01' AND '2023-12-31'`
3. **模糊查询注意**：
   - ❌ `LIKE '%test'` (前缀模糊，索引失效)
   - ✅ `LIKE 'test%'` (后缀模糊，索引有效)
4. **OR 要小心**：
   - 如果 `WHERE a=1 OR b=2`，除非 a 和 b 都有索引，否则可能全表扫描。
